# GitHub 观测站

AstrBot 插件 `astrbot_plugin_github_observer`，支持监看指定市场插件和 GitHub 仓库，市场插件可同时监看关联仓库，按北京时间生成日报、周报、月报，并向订阅所在群聊或私聊推送。

## 功能

| 目标 | 基础指标 | 可选指标 |
| --- | --- | --- |
| 市场插件 | 下载总量及增量、下载排名及升降、Star 总量及净增减 | 市场版本变更 |
| GitHub 仓库 | Star、Fork 总量及净增减 | 分支提交活动、Release、Issue、PR |

- 指标统一在目标配置中选择，每个会话分别设置报告周期和事件提醒。
- 市场目标可开启“同时监看 GitHub 仓库”，自动关联市场记录中的仓库地址。开关打开后展开仓库附加指标复选框，选项与 GitHub 仓库类型一致。
- 同一 GitHub 仓库配置多个目标时，共用一次仓库采集；指定的不同分支分别采集。同一市场插件的多个目标共用市场采集。
- Issue 与 PR 分开统计；PR 合并不重复计为“关闭未合并”。
- SQLite 保存历史、采集游标、订阅和推送队列；重载后继续采集。
- 接口失败、限流、分页超限和采样缺口明确显示，不把失败结果当作零。
- 全部命令仅限 **AstrBot 管理员**；API Key 禁止管理员角色时，同样禁止调用。

## 安装

要求 AstrBot `>=4.27,<5`。依赖仅为 `aiohttp>=3.9,<4`。

在 AstrBot 插件管理页面使用“从本地文件安装”，上传本插件 ZIP。也可以将源码放到 `data/plugins/astrbot_plugin_github_observer/`，然后通过插件管理加载。

安装后在插件配置页添加监看目标，保存并重载。默认目标列表为空，不会发起市场或仓库采集。发送 `/观测站 帮助` 查看命令。

## 配置

`targets` 使用 AstrBot 的模板列表，分别选择“市场插件”和“GitHub 仓库”。

| 字段 | 含义 |
| --- | --- |
| `alias` | 可选别名，留空或省略时，命令直接使用市场 ID 或 `owner/repo`；填写时支持中文，不能含空白、逗号、`/` 或 `|` |
| `plugin_id` | 市场模板专用，填写市场 `作者/插件名`；作者可能不同于 GitHub 所有者 |
| `repo` | 仓库模板专用，填写 `owner/repo`，不带 URL 或 `.git` |
| `branch` | 仓库模板专用，留空监看默认分支，也可指定一个分支 |
| `metrics` | 附加指标，通过中文枚举复选框选择；不勾选时只监看该类目标的基础指标；采集、报表和动态查询统一使用配置中启用的全部指标 |
| `github_enabled` | 市场模板专用，“同时监看 GitHub 仓库”开关，默认关闭 |
| `github.metrics` | 市场模板专用，开启上述开关后显示；选项与 GitHub 仓库的附加指标相同 |

市场插件可勾选 **市场版本变更**；GitHub 仓库可勾选 **提交活动、Release 发布、Issue、PR**。市场插件的下载量、下载排名和 Star、GitHub 仓库的 Star 和 Fork 为基础指标，始终采集，无需勾选或手动输入指标名称。

市场插件的下载量、下载排名、Star、市场版本全部使用市场接口数据。未开启关联仓库监看时，不请求 GitHub，不需要 GitHub Token。Star 使用市场的 `stars` 字段；缺失或无效时明确提示。

开启关联仓库监看后，自动使用市场记录中的 `repo` 地址，基础统计增加 Fork，可勾选提交活动、Release、Issue、PR；Star 仍只显示市场数值。提交活动使用关联仓库的默认分支。关闭开关会保留已勾选选项和历史，但停止该目标的仓库采集，报表与动态查询也不再包含仓库指标。

关联仓库与独立配置的同一 GitHub 仓库共用采集和历史，不重复请求。仓库采集失败或市场未提供有效 GitHub 地址时，告警会说明原因，市场指标仍正常采集。关联地址变更后按新仓库查询，旧仓库历史继续保留且不混算；本轮市场采集失败时跳过关联仓库采集，不使用旧地址继续请求。

目标标识必须唯一。多个未设置别名的目标若具有相同 ID（包括同仓库的不同分支），请为其中一个设置别名；插件会明确提示冲突，不自动猜测目标。市场 ID 和 `owner/repo` 在命令中不区分大小写，自定义别名区分大小写。

| 公共配置 | 默认值 | 说明 |
| --- | --- | --- |
| `github_token` | 空 | 可选，推荐填写以提高 GitHub 请求额度 |
| `market_url` | `https://cloud.astrbot.app/api/v1/market/plugins.json` | 当前官方市场 JSON 源 |
| `poll_minutes` | `60` | 采集间隔，范围 5～1440 分钟 |
| `request_timeout` | `30` | 单次请求超时，范围 5～120 秒 |
| `max_pages` | `50` | 单个分页接口最多 1～500 页，每页最多 100 条 |
| `push_time` | `09:00` | 北京时间的周期报告发送时间 |

GitHub Token 只发送至 `api.github.com`，不会发送到市场源、写入统计数据库或显示在报告中。配置本身由 AstrBot 保存，请保护其配置文件。公开仓库可不填 Token，但 GitHub 匿名核心 API 通常只有每 IP 每小时 60 次请求额度；监看多个仓库或 Issue/PR 较活跃时推荐配置 Token。

监看私有仓库时，Token 需要该仓库相应的只读权限：Metadata、Contents、Issues、Pull requests，具体取决于所选指标。本插件只调用读取 API，不修改 GitHub 资源。

完整 JSON 配置示例（也可直接通过可视化配置页面填写）：

```json
{
  "targets": [
    {
      "__template_key": "market",
      "alias": "绘图插件",
      "plugin_id": "Sham1k0/astrbot_plugin_get_px",
      "metrics": ["version"],
      "github_enabled": true,
      "github": {
        "metrics": ["commits", "release", "issues", "prs"]
      }
    },
    {
      "__template_key": "github",
      "alias": "AstrBot",
      "repo": "AstrBotDevs/AstrBot",
      "branch": "",
      "metrics": ["commits", "release", "issues", "prs"]
    }
  ],
  "github_token": "",
  "market_url": "https://cloud.astrbot.app/api/v1/market/plugins.json",
  "poll_minutes": 60,
  "request_timeout": 30,
  "max_pages": 50,
  "push_time": "09:00"
}
```

仅接受当前配置字段，未知或缺失字段直接报错。市场源必须使用 `$meta.schema_version=1` 和规范的 `作者/插件名` 键；旧版无 schema 的源、仅有插件名的旧键和自动备用源不受支持。发生重定向时明确报错，请填写当前地址。

## 命令

```text
/观测站 帮助
/观测站 列表
/观测站 状态
/观测站 刷新

/观测站 日报
/观测站 日报 AstrBot
/观测站 日报 AstrBot 2026-10-19
/观测站 周报 AstrBot 2026-10-19
/观测站 月报 AstrBot 2026-09-01

/观测站 动态 AstrBot
/观测站 动态 AstrBot 20

/观测站 订阅 AstrBot 日报,周报,月报
/观测站 订阅 AstrBot 周报 --提醒 release
/观测站 订阅 绘图插件 日报,月报 --提醒 version
/观测站 订阅 绘图插件 周报 --提醒 version,release
/观测站 订阅列表
/观测站 退订 AstrBot
```

未设置 `alias` 时，直接用目标 ID，例如：

```text
/观测站 日报 AstrBotDevs/AstrBot
/观测站 订阅 AstrBotDevs/AstrBot 周报
/观测站 退订 AstrBotDevs/AstrBot
```

上面三条示例适用于未填写仓库别名的配置；填写了别名时使用别名。含空格的市场 ID 在命令中使用引号包裹。

配置页面通过复选框选择指标，采集、手动报表、订阅推送和动态查询自动使用目标配置中启用的全部指标。配置保存并重载后，现有订阅自动跟随，无需重新订阅。指标标识如下：

| 标识 | 指标 | 支持的目标 |
| --- | --- | --- |
| `downloads` | 下载量，市场目标必选 | 市场插件 |
| `download_rank` | 下载排名，市场目标必选 | 市场插件 |
| `stars` | Star，两类目标均为基础指标 | 两类目标 |
| `version` | 市场版本变更 | 市场插件 |
| `forks` | Fork 总量及净增减，仓库基础指标 | GitHub 仓库、开启关联仓库的市场插件 |
| `commits` | 提交活动，关联仓库使用默认分支 | GitHub 仓库、开启关联仓库的市场插件 |
| `release` | 已发布 Release，含预发布 | GitHub 仓库、开启关联仓库的市场插件 |
| `issues` | Issue 数量与新增、关闭、重开事件 | GitHub 仓库、开启关联仓库的市场插件 |
| `prs` | PR 数量与新增、关闭未合并、合并、重开事件 | GitHub 仓库、开启关联仓库的市场插件 |

`--提醒` 使用区分大小写的英文标识，以英文逗号分隔，可选 `version,release,issues,prs,commits`，必须属于目标配置中已启用的指标；未启用时订阅会明确报错。不填则只发送周期报告。提醒在下一次成功采集后发送，延迟取决于采集间隔，不使用 Webhook。

配置停用已订阅的某个提醒指标后，该订阅的全部事件提醒暂停，周期报告继续使用当前配置。`/观测站 状态` 和 `/观测站 订阅列表` 会明确提示原因。已排队的事件提醒同样暂停发送；重新启用对应指标后恢复，或重新订阅调整提醒设置。

升级时数据库会一次性移除订阅中固定保存的指标列表，保留订阅周期、提醒设置、历史采样和推送队列；升级后所有订阅统一跟随目标配置。

每个会话对每个目标标识只有一条订阅。再次订阅覆盖原设置，从当前时间生效，并删除旧订阅的待发送消息。`退订` 只影响当前会话；添加、移除或更换别名会改变目标标识，旧订阅暂停，需要重新订阅。已设置别名时，修改目标地址会让同别名订阅跟随新目标，历史按源身份隔离。

手动报告无目标参数时查询全部配置目标。多目标日报、周报、月报共用顶部的标题、统计周期和采样时间，各目标分别显示指标和采集告警。共同的完整性提示和提交统计说明只展示一次，个别目标的完整性提示保留在对应目标下。无日期时查询当前周期并标注“统计中”；指定日期查询该日、该日期所在周或该日期所在月。手动报告与动态查询均使用目标当前配置中的指标，与是否订阅无关。

日、周、月报保留指标名称并增加 Emoji：📥 下载、🏆 下载排名、⭐ Star、🍴 Fork、🏷️ 市场版本、📝 提交、📦 Release、🐛 Issue、🔀 PR。⬆️ 表示数量增加或排名上升，⬇️ 表示数量减少或排名下降，➖ 表示无变化；⏳ 表示采样待积累，⚠️ 标识注意事项和采集异常。手动查询与订阅报告使用同一格式。

## 统计口径

### 时间与采样

全部按北京时间：自然日 `[00:00, 次日00:00)`、周一至下周一、月初至下月月初。日报在次日、周报在下周一、月报在下月 1 日的 `push_time` 推送。

启动、正常采集时点和北京时间零点都会安排采集。后台每 30 秒检查，网络耗时、平台启动时间及 API 延迟都会影响实际采样时间；这不是精确的市场交易日志。

下载、Star、Fork 增量以实际快照计算。优先使用周期起点之前最近一次快照作为基线，终点取不晚于周期结束的最后一次快照；边界缺失或基线过旧会提示，不插值、不估算。每份报告只在顶部展示一行采样时间：每个目标取本周期内相关指标最新一次有效采样或事件采集时间，多个目标时间不同时显示最早到最晚的范围，相同则显示一个时间；不逐项列出采样时段。

**下载排名**按市场接口中全体插件的累计 `download_count` 从高到低计算，同下载量使用并列名次（1、1、3）。只保存已配置插件的排名快照，不保存全市场历史，不增加接口请求。任一市场记录缺少有效下载量时，当次排名不可用并告警，其他有效指标继续采集。

下载排名是市场插件的基础指标，手动查询和订阅的日报、周报、月报均自动包含。报告显示周期末最后一次可用采样的排名，以及相对期初基线的上升、下降名次或持平；周期尚未结束时显示最近一次排名。只有一次采样时显示当前名次并提示变化待积累；周期中途开始则按实际采样时段计算。示例：`🏆 下载排名：第 500 名｜⬆️3 名`。

排名从 v0.1.3 升级后的首次成功采集开始记录，之前未记录的周期显示无可用采样。已有订阅自动包含排名，无需重新订阅。

“本周期记录不完整，统计仅覆盖已记录时段”表示部分指标在周期开始后才开始记录。例如 11:00 为 212、12:00 为 213，⬆️1 仅覆盖这一小时，无法据此推算当天零点以来的完整下载量。持续运行并成功完成零点附近的采集后，后续周期可以使用相应基线；中断采集仍会提示缺口。

从 v0.1.2 起，市场 Star 在市场目标自己的快照中累计；既有下载、版本历史和订阅保留，旧版从 GitHub 获取的 Star 历史保留在仓库来源下，不与市场接口数据混算。升级后市场 Star 的首次成功采集建立新基线。

首次只有一个快照时显示“待积累”。下载量按期末减期初计算；如果期间发生回退，报告会提示“期间发生计数回退”，并保留实际净变化（期末低于期初时显示负值）。Star、Fork 也允许负的净变化。市场下载量采用平台公布的累计计数，不代表独立用户数，源数据刷新可能晚于实际下载。

### 事件

- **市场版本**：比较市场 `version` 字段，按观测时间记录变更，包括回退；不猜测版本字符串的大小关系，也不等同于 GitHub Release。首次启用只建立基线，轮询期间经过多个版本时可能只能观测到最终版本。
- **Release**：按 `published_at` 统计已发布版本，包括带标记的预发布；草稿不计。首次启用不导入旧 Release；同一个 Release 编辑说明不会重复计为新版本。不监看独立 Tag。
- **Issue/PR**：通过更新时间增量列举项目，再读取对应时间线，按事件时间记录新增、关闭、重开、合并；事件 ID 去重，新增使用项目编号去重。查询有 5 分钟重叠窗口，采集失败不推进游标。服务器延迟超过重叠窗口、被删除的项目或无法读取的事件仍可能无法恢复，历史报告不是平台审计记录。
- **提交**：比较所选分支上次与本次的 HEAD，按 SHA 去重；统计新进入该分支且此前未观测到的提交。使用首次观测时间归入周期，不使用可被作者设置的提交日期冒充推送时间；离线期间的提交在恢复采集时归入恢复所在周期。首次采集只记录 HEAD。空仓库之后出现首批提交时计为新增。
- **分支历史改写**：比较接口能识别回退或分叉时记录提示。旧 SHA 已无法比较、分支删除或权限变化时明确报错并保留游标，不悄悄重置基线。默认分支更换后，新分支单独建立基线。

Issue/PR 当前未关闭数量来自遍历全部 open 条目并区分 PR，不直接使用 GitHub 混合的 `open_issues_count`。计数 API 和事件 API 为不同请求，报告统一展示最新有效采样时间。

所有事件从指标首次启用后开始累计。周期中途开始监看会标明统计不完整，不回填启用之前的历史。停用指标保留历史和游标，之后重新启用会从保留进度继续；提交和市场版本仍按恢复后的观测时间计入。

### 推送与恢复

正常情况下同一订阅、同一周期只排队一次。报告消息及进度在同一 SQLite 事务中写入。重启后补排订阅建立以来遗漏的完整周期，每轮最多为每个周期类型补排 20 期，后续轮次继续；没有历史采样的报告会显示数据缺口。

发送失败后指数退避，最多每小时重试一次；`/观测站 状态` 可查看待发送数量和错误。目标从配置移除后暂停其推送，退订会清理待发送队列。文本较长时分成多条消息，每段单独记录发送结果。

平台发送与本地确认不能组成同一事务：若进程恰好在平台收到消息后、本地记账前退出，恢复时可能重复发送该条。主动消息也受平台能力和权限限制。

## 数据与排障

数据保存在：

```text
data/plugin_data/astrbot_plugin_github_observer/observer.sqlite3
```

历史默认持续保留。备份时先停用插件，再复制该目录；不要在数据库运行期间只复制主文件而遗漏 WAL 文件。插件源码目录不保存 Token 或运行数据。

遇到问题先执行 `/观测站 状态`。GitHub 限流会停止继续请求，等恢复后再在下一次采集时重试；市场采集不依赖 GitHub 配额。分页超限可提高 `max_pages`，插件不会使用被截断的数据推进相应事件游标。

## 开发验证

测试依赖：`pytest`、`pytest-asyncio`、`ruff`，以及可导入的 AstrBot 开发环境。默认从插件相邻的 `AstrBot/` 目录导入框架；也可通过 Python 模块路径提供 AstrBot。

```text
python -m pytest -q
ruff format --check .
ruff check .
```

测试隔离到临时 AstrBot 根目录，不发送真实平台消息。覆盖统计边界、采集游标、PR 合并、会话隔离、重启恢复及 AstrBot 实际命令与消息接口。
